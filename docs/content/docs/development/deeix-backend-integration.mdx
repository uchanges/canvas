# DEEIX 后端集成

## 架构边界

无限画布只负责 React 画布交互、节点编排和流式结果展示。DEEIX Go 服务是账号、权限、模型、项目、文件、任务、计费与审计的事实源。浏览器不得保存或发送上游 API Key，也不得直接请求模型服务商。

推荐同源部署：画布位于 `/canvas/`，DEEIX API 位于 `/api/v1/`，登录页由 `DEEIX_LOGIN_URL` 指定。Vite `base` 与 React Router `basename` 必须保持一致。

## 项目与文件接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` / `POST` | `/api/v1/canvas/projects` | 项目列表、创建项目 |
| `GET` / `PATCH` / `DELETE` | `/api/v1/canvas/projects/:id` | 读取、修改、删除项目 |
| `PUT` | `/api/v1/canvas/projects/:id/scene` | 使用 revision 保存完整场景 |
| `POST` | `/api/v1/files` | 上传节点媒体 |
| `GET` | `/api/v1/files/:file_id/content` | 鉴权读取媒体内容 |

场景持久化的是节点、连线、视口、文件 ID 和元信息；不能写入 `blob:` URL、浏览器存储键或上游凭据。服务端必须按照当前用户校验项目、文件和任务归属。

## 模型与任务接口

| 能力 | 路径 | 任务语义 |
| --- | --- | --- |
| 图片模型 | `GET /api/v1/image/models` | 返回可访问模型与能力 |
| 文本模型 | `GET /api/v1/models` | 返回当前用户平台模型 |
| 图片任务 | `POST /api/v1/canvas/projects/:id/tasks/image` | 创建可恢复 Job |
| 图片 SSE | `GET /api/v1/image/jobs/:id/stream` | 订阅 Job 状态与结果 |
| 文本流 | `POST /api/v1/canvas/projects/:id/tasks/text/stream` | 请求生命周期内流式输出 |
| 视频流 | `POST /api/v1/canvas/projects/:id/tasks/video/stream` | 请求生命周期内流式输出 |
| 音频流 | `POST /api/v1/canvas/projects/:id/tasks/audio/stream` | 请求生命周期内流式输出 |

视频、音频流中的 `runId` 仅用于当前请求事件，不可持久化为图片 Job ID。页面刷新时，前端必须把尚未完成的文本、视频、音频节点标记为中断；只有图片 Job 才可按任务 ID 恢复。

所有接口采用 DEEIX 响应包络并返回稳定错误码。前端 API 封装应统一处理 Bearer Access Token、`credentials: include`、401 刷新、SSE、409 场景冲突和用户可读错误信息。

## 保存与部署

前端先更新 Zustand 保持编辑流畅，再防抖保存场景。同一项目同一时刻只允许一个保存请求；保存中产生的新版本必须在前一次结束后再次保存。关闭页面时只能使用离开提示，不能承诺异步保存一定完成。

Docker 通过运行时 `config.js` 注入 `DEEIX_API_BASE_URL` 和 `DEEIX_LOGIN_URL`。子路径部署需要在构建阶段设置 `VITE_BASE`，并由反向代理将该路径映射到画布静态资源；该组合仍需生产环境人工验证。

## 本地 Agent

仓库保留本地 Agent 相关源码供开发分支使用，但平台版不挂载面板、不自动连接，也不在导航或文档导航中暴露入口。它不能作为 DEEIX 平台的业务能力或数据来源。
